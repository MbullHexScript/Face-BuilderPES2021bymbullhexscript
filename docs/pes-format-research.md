# Riset format wajah PES 2021 dan audit tooling

Audit TASK 03 ini memisahkan bukti source code dari hasil eksekusi lokal. Repository dibaca sebagai referensi; addon, executable komunitas, dan konfigurasi Blender tidak dipasang atau dijalankan oleh audit ini. Klaim kompatibilitas pada README bukan bukti round-trip PES 2021.

Pada awal pemeriksaan project belum berisi sampel PES. Sesudah itu pengguna mengizinkan parent task membaca konfigurasi LiveCPK dan menyalin satu aset pemain ke workspace terpisah. Hasil inspeksi sampel dan hash sumber harus dibaca di [laporan validasi pipeline](pes-pipeline-validation.md); dokumen ini tidak menggantikan bukti tersebut.

## Struktur format yang dapat dijadikan dasar inspector

Semua offset berikut dihitung dari awal file dan little-endian, kecuali disebut lain. Ini fakta layout pada implementasi referensi, bukan spesifikasi resmi Konami maupun validasi seluruh varian.

### FMDL

Header yang dibaca upstream berukuran 56 byte: magic `FMDL` pada 0x00, versi u32 pada 0x04, offset descriptor u64 pada 0x08, dua bitmap u64 pada 0x10/0x18, jumlah block u32 pada 0x20/0x24, lalu offset/panjang section u32 pada 0x28/0x2C dan 0x30/0x34. Versi writer adalah bit pattern `0x4001EB85`.

Descriptor section 0 berukuran 8 byte: ID u16, jumlah entry u16, offset relatif u32. Descriptor section 1 berukuran 12 byte: ID, offset relatif, panjang, semuanya u32. Ukuran entry section 0 ditentukan per-ID; ID yang tidak dikenal tidak boleh diterjemahkan menjadi jumlah mesh/tulang secara spekulatif. Source juga memperingatkan beberapa panjang section 1 tidak akurat dan memperlakukan block 3 secara khusus. Inspector ketat sebaiknya mencatat anomali batas tanpa langsung mengklaim file tidak dapat dibaca game. [FmdlFile.py](https://github.com/the4chancup/pes-fmdl-blender/blob/231093d3a056176b8d6e33e79d13f5563b27b985/pes-fmdl/FmdlFile.py).

### FTEX

Header 64 byte: `FTEX` pada 0x00, versi float32 pada 0x04, format pixel u16 pada 0x08, width/height/depth u16 pada 0x0A/0x0C/0x0E, mip count u8 pada 0x10, flags u16 pada 0x12, texture type u32 pada 0x1C, jumlah FTEXS u8 pada 0x20. Tabel frame mulai 0x40, ukuran 16 byte: offset/u32, ukuran uncompressed/u32, compressed/u32, indeks mip/u8, nomor FTEXS/u8, jumlah chunk/u16. Header chunk berukuran 8 byte dan offsetnya relatif terhadap frame.

Pembaca upstream menangani zlib, mipmap, cubemap dan beberapa format BC/DXGI, tetapi menolak FTEXS eksternal. Header sesuai bukan bukti payload tekstur terdekompresi atau warna/normal benar. Nilai format dan layout harus dibedakan dari decoding aktual. [Ftex.py](https://github.com/the4chancup/pes-fmdl-blender/blob/231093d3a056176b8d6e33e79d13f5563b27b985/pes-fmdl/Ftex.py).

FtexTool mempunyai [test round-trip berbasis DDS sintetis](https://github.com/Atvaark/FtexTool/blob/b92003125be2a05e737f0388e1e0e7e0db240d3f/FtexTool.Test/RoundtipTest.cs), termasuk perbandingan buffer. Keberadaan test pada repository tidak sama dengan test tersebut lulus di lingkungan ini, apalagi bukti tekstur wajah PES 2021 lolos game.

### FPK dan FPKD

Header 48 byte: magic enam byte `foxfpk`, type byte pada 0x06, platform tiga byte pada 0x07 (`win` pada writer yang diperiksa), ukuran u32 pada 0x0A, marker u32 pada 0x20, file count u32 pada 0x24, reference count u32 pada 0x28. Writer Python membedakan FPKD dengan byte ASCII `d`; FPK menggunakan nol. Entry berukuran 48 byte: offset payload, panjang payload, offset nama, panjang nama (slot 8-byte), lalu digest 16-byte. Digest pada implementasi Python adalah MD5 **nama**, bukan payload. [fpk.py](https://github.com/the4chancup/pes-file-tools/blob/9cdfcc5ce902a8908a851787298cf8f79862a3c6/lib/pes_file_tools/fpk.py).

GzsTool mengonfirmasi header/table dan membaca reference entries 16-byte setelah file entries. Implementasinya memakai low-32-bit plus padding untuk beberapa slot. Nama bisa tidak terselesaikan dan memerlukan kamus; digest nama yang tidak cocok tidak boleh otomatis diberi label kerusakan payload. [FpkFile.cs](https://github.com/Atvaark/GzsTool/blob/384cb81155ada82716c21b95035b5306b1c0d9cf/GzsTool.Core/Fpk/FpkFile.cs), [FpkString.cs](https://github.com/Atvaark/GzsTool/blob/384cb81155ada82716c21b95035b5306b1c0d9cf/GzsTool.Core/Fpk/FpkString.cs).

### face_diff.bin dan susunan aset

Source face modifier membaca magic `FACE` dan triplet float pada 0x08, 0x3C, 0x150, 0x160 untuk parameter yang ditafsirkan sebagai skala mata, posisi mulut, serta mata kanan/kiri. Ada remapping sumbu. Logika mulut berubah ketika `oral.fmdl` tersedia. Karena itu inspector awal sebaiknya menyebutnya triplet mentah dengan interpretasi referensi, bukan skema universal yang sudah terbukti. [Implementasi leus](https://github.com/leus/PesFacemod/blob/05c5a086d48f75f4d36d529f6c7c21d7b58893fb/PesFacemod/PesFacemod.py).

Nama `face_high.fmdl`, `hair_high.fmdl`, `oral.fmdl`, dan `face_diff.bin` digunakan oleh tool MjTs, tetapi adanya cabang ketika oral tidak tersedia menunjukkan bahwa daftar itu tidak boleh dipaksakan sebagai struktur wajib semua wajah. Path tekstur yang dibangun tool adalah konvensi implementasinya, bukan hasil inventaris sampel saat ini. [Entry modifier MjTs](https://github.com/MjTs140914/PES_Face_Hair_Modifier/blob/e9bb728935f2a3ad67dd47116b2f2cebc1237fea/Blender%202.91/PES_Face_Hair_Modifier.py).

## Skeleton, UV, material, dan risiko konversi GLB

Adapter upstream mengonversi sumbu untuk Blender, membuat vertex groups dari bone mapping, mengimpor UV per-layer, dan menyimpan shader/technique/parameter/texture-role serta alpha/shadow flags sebagai properti khusus. Material game tidak identik dengan material Principled Blender. [IO.py](https://github.com/the4chancup/pes-fmdl-blender/blob/231093d3a056176b8d6e33e79d13f5563b27b985/pes-fmdl/IO.py).

Port modern mempunyai material node heuristik, penanganan normal map, alpha, serta warna vertex berbasis CORNER. Adanya implementasi tersebut menunjukkan upaya adaptasi API, bukan ekuivalensi hasil shader FOX Engine. [IO.py port modern](https://github.com/Syahroel/PES-eFootball-Face-Hair-Modifier-AddOns---Blender-4.5-Edition-Upgrade-By-Ruls/blob/90a4487fda13f85f7a77c1aa025bfc9edda18c41/Data/IO.py).

Implikasi desain (inferensi audit): GLB cocok sebagai artefak preview, tetapi belum layak dijadikan satu-satunya sumber ekspor kembali. Identitas bone dan parent, bind/rest transforms, pengaruh skin per vertex, UV seams, normals/tangents, urutan mesh, bounding boxes, shader/texture roles, dan flag PES harus dipertahankan sebagai metadata terpisah. Re-import GLB tanpa metadata itu dapat tampak benar sekaligus kehilangan informasi game.

Untuk round-trip yang sah, bandingkan set bone dan hierarki, jumlah/indeks mesh, atribut vertex dan UV per-corner, sum serta distribusi skin weights, texture references, shader parameters dan flag sebelum/sesudah. Bandingkan toleransi float secara eksplisit; jangan mensyaratkan hash seluruh FMDL sama jika writer melakukan padding/reordering. Hash sama berguna untuk bukti sumber tidak berubah, bukan pengganti evaluasi geometri atau uji game.

## Keputusan untuk fondasi prototype

1. Inspector read-only mandiri dapat memverifikasi signature, ukuran, field header, table/entry ranges dan digest yang algoritmanya jelas. Keluaran harus membedakan diketahui, tidak didukung, dan tidak diverifikasi.
2. Import adapter, export adapter, dan Blender worker tidak boleh mengklaim sukses hanya karena interface tersedia. Pemilihan addon membutuhkan lisensi/provenance yang cukup dan uji pada executable Blender terisolasi dengan versi pasti.
3. Jalur yang layak diuji berikutnya: salinan aset terisolasi → inspeksi → decode/import terverifikasi → GLB preview plus metadata pendamping → ekspor FMDL/tekstur ke output baru → perbandingan struktur. Keberhasilan tahap terakhir tetap bukan bukti runtime PES tanpa uji game terpisah yang diotorisasi.
4. Jangan mengikuti petunjuk addon lama untuk menimpa konfigurasi Blender utama. Jangan menjalankan fungsi exporter yang membuka sumber `r+b` pada sumber asli. Kerjakan hanya salinan dengan manifest/hash dan output baru.

Tidak ada addon dalam audit ini yang dinyatakan sudah membuktikan round-trip wajah PES 2021 pada Blender modern. Hasil implementasi lokal, termasuk sampel yang akhirnya tersedia, dilaporkan secara terpisah dalam [TASK 03](task-03.md) dan [validasi pipeline](pes-pipeline-validation.md).
